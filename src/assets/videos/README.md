# Видео первого экрана

Положите сюда ролики клиники:

```
video-1.mp4          ← стартовый главный ролик
video-1.mobile.mp4   ← (необязательно) облегчённая версия того же ролика для телефонов
video-2.mp4          ← миниатюра 1
video-3.mp4          ← миниатюра 2
video-4.mp4          ← миниатюра 3
```

Порядок берётся по имени файла: первый по алфавиту становится главным,
остальные — миниатюрами под ним. Форматы: `.mp4`, `.webm`, `.m4v`.
Файл `<имя>.mobile.mp4` отдельным роликом не считается: это версия
`<имя>.mp4` для экранов до 767 px и для миниатюр.

Рядом можно положить кадр-постер с тем же именем — `video-1.jpg`,
`video-1.png` или `video-1.webp`. Сборка сожмёт его в WebP и покажет,
пока ролик не загрузился. Постер стоит положить обязательно: ролик
грузится не сразу (см. ниже), а при Save-Data и «уменьшении движения»
посетитель видит только постер.

## Что делает сборка

`npm run build` копирует ролики в `dist/assets/videos/` (и в `assets/videos/`
рядом с копией `index.html` для открытия двойным кликом), добавляя к имени
хеш содержимого: `video-1.a39de05e.mp4`. Ролики отдаются с кешем на год,
и хеш гарантирует, что заменённый файл посетители увидят сразу. Старые
копии сборка удаляет сама. Файлы **не** кодируются в base64 — иначе
один HTML вырос бы на десятки мегабайт.

На сайте ролик подключается от корня (`/assets/videos/…`), поэтому
играет на любой странице, в том числе `/ru/services/therapy`.

## Когда ролик загружается

- Сначала виден только постер (`preload="none"`).
- Ролик подключается, когда плеер попал в кадр и страница уже
  загрузилась. На телефоне плеер ниже первого экрана — ролик начнёт
  грузиться при прокрутке к нему.
- Save-Data, сеть 2G или `prefers-reduced-motion` — остаётся постер;
  ролик загрузится, только если нажать Play.

## Как подготовить файл

Рекомендации: H.264 (`libx264`), ширина около 1280 px, без звука
(ролик всё равно проигрывается в `muted`), `-movflags +faststart`,
до ~8 МБ на файл — сборка предупредит, если файл тяжелее.

Так пережат текущий `video-1.mp4` (137 с, 1280×720, было 18 МБ → 4,5 МБ):

```bash
# основная версия, ~260 кбит/с, два прохода
ffmpeg -y -i исходник.mp4 -an -map_metadata -1 -vf scale=1280:-2:flags=lanczos \
  -c:v libx264 -preset veryslow -b:v 260k -maxrate 780k -bufsize 1560k \
  -profile:v high -level:v 4.0 -pix_fmt yuv420p -x264-params aq-mode=3 \
  -pass 1 -f mp4 /dev/null
ffmpeg -y -i исходник.mp4 -an -map_metadata -1 -vf scale=1280:-2:flags=lanczos \
  -c:v libx264 -preset veryslow -b:v 260k -maxrate 780k -bufsize 1560k \
  -profile:v high -level:v 4.0 -pix_fmt yuv420p -x264-params aq-mode=3 \
  -pass 2 -movflags +faststart video-1.mp4

# версия для телефонов: те же команды с scale=854:-2, -b:v 140k -maxrate 420k
# -bufsize 840k и выходным файлом video-1.mobile.mp4 (~2,5 МБ)
```

Битрейт подбирайте под длину ролика: размер ≈ битрейт × длительность
(260 кбит/с × 137 с ≈ 4,5 МБ). Для коротких роликов (6–15 с) можно взять
1000–1500 кбит/с — файл всё равно останется в пределах пары мегабайт.

Пока папка пуста, первый экран показывает фотографию `src/assets/photos/hero.*`
— вёрстка и анимации при этом не ломаются.

## Как посмотреть, как это выглядит, до съёмки роликов

В `_sample/` лежат четыре коротких тестовых клипа (по 26–31 КБ), на которых
проверялись переключение, Play/Pause и swap. Чтобы увидеть первый экран
с видео, скопируйте их на уровень выше и пересоберите:

```bash
cp src/assets/videos/_sample/* src/assets/videos/
npm run build
```

Папка `_sample/` сборкой не читается — она смотрит только на файлы в корне
`src/assets/videos/`. Перед публикацией замените тестовые клипы настоящими
и удалите `_sample/`.
