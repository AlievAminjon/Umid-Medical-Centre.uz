# UMID Medical Centre — сайт стоматологической клиники

Готовый к публикации сайт в дизайне **UMID SIGNATURE**: premium medical + editorial.
Файл `index.html` самодостаточен — внутри стили, скрипты, логотипы и фотографии.
Его можно открыть двойным кликом (адреса тогда будут вида `index.html#/ru/services`).
На хостинге у страниц настоящие адреса — `/ru/services`; сайт опубликован на Vercel,
правила для сервера — в `vercel.json` (см. раздел 4.1).

---

## 1. Что внутри

- **6 языков**: русский (по умолчанию), узбекский, английский, испанский, французский, немецкий.
  Переключение мгновенное, без перезагрузки. Язык запоминается и остаётся в адресе — ссылкой можно поделиться:
  `/ru/services/therapy`, `/de/contacts`.
- **13 типов страниц**: главная, о клинике, услуги + 8 отдельных страниц услуг, цены, врачи + профили,
  отзывы, пациентам, контакты, политика конфиденциальности, правила оказания услуг, 404.
- **Запись на приём** в двух местах: модальное окно из любой кнопки и большая секция «Удобная запись»
  на главной и в контактах. Общая валидация, общее состояние успеха, дублирование заявки в Telegram/WhatsApp.
  Заявка уходит в Telegram клиники через функцию `api/booking.js` (раздел 4.2).
- **Мобильная панель снизу**: Позвонить · Telegram · WhatsApp · Записаться.
- **Плавающие кнопки на десктопе** с раскрывающейся подписью при наведении.
- **SEO**: для каждой страницы и каждого языка свои title, description, canonical, hreflang, Open Graph
  и микроразметка schema.org (`Dentist` + `MedicalClinic` + `LocalBusiness`, BreadcrumbList, FAQPage).
  Сборка кладёт рядом `robots.txt` и `sitemap.xml` — все страницы × 6 языков с альтернативами hreflang.

## 2. Что нужно заменить перед запуском

Всё, что зависит от клиники, собрано в одном файле — `src/data/clinic.js`.
Ничего не выдумано: где данных нет, стоит честная заглушка.

| Что | Где | Сейчас |
|---|---|---|
| Ссылка на Telegram | `CLINIC.telegram` | ссылка по номеру, заменить на `@username` клиники |
| Instagram | `CLINIC.instagram` | `null` — блок появится после указания ссылки |
| Точка на карте | `CLINIC.coords` | `null` — показывается стилизованная схема со ссылками на Google и Яндекс |
| Куда уходит заявка | `CLINIC.bookingEndpoint` | `/api/booking` → Telegram клиники. Нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` на Vercel (раздел 4.2); пока их нет — демо-режим, в браузере ничего не сохраняется |
| Цены | `PRICES` | пусто — везде «Спросить цену». Впишите `{ caries: 250000 }` — сумма появится сама |
| Врачи | `DOCTORS` | 4 карточки-заглушки. Добавьте `name`, `role`, `experience`, `education`, `langs`, `photo` |
| Отзывы | `REVIEWS`, `REVIEW_SOURCES` | пусто — «Здесь будут реальные отзывы». Ссылки на площадки добавляются в `url` |
| Документы | `DOCUMENTS` | лицензия и правила ждут файлов, у остальных статус «Готовится» |
| Фотографии | `src/assets/photos/` | загружен фасад клиники; остальные слоты ждут съёмки — см. раздел 3 |
| Домен | `SITE_URL` | `https://umid-medical.uz` — нужен для canonical, hreflang, `sitemap.xml` и `robots.txt`. Домен нужно подключить к проекту на Vercel |

**Важно про цены.** Пока `PRICES` пуст, на сайте нигде не появляется ни одной цифры — вместо неё
кнопка «Спросить цену» со ссылкой в мессенджер. Это осознанное решение: лучше живой контакт,
чем выдуманная сумма. Оговорка «окончательная стоимость определяется после осмотра, диагностики
и составления индивидуального плана лечения» стоит на всех страницах с ценами.

**Важно про оборудование.** Конкретные модели и производители не указаны нигде: клиника
их ещё не подтвердила. В секции «Технологии» описаны только процессы приёма, а бейдж
«Оснащение уточняется» стоит на месте будущего перечня.

## 3. Как добавить фотографию

Кода писать не нужно. Три шага:

```
1. Назовите файл ключом слота   →  facade.png
2. Положите в                    →  src/assets/photos/
3. Пересоберите                  →  npm run build
```

Сборка сама повернёт снимок по EXIF, ужмёт до 1600 px по ширине, переведёт
в WebP и подставит вместо заглушки. Подходят **png, jpg, webp, avif** любого
размера — фасад клиники ужался с 2036 КБ до 78 КБ.

**Ключи слотов** (полный список — в `src/data/clinic.js`):

| Файл | Куда попадёт | Ориентация |
|---|---|---|
| `facade.*` | «Клиника изнутри», мозаика на странице «О клинике» | горизонтальная |
| `reception.*` | ресепшен на главной и в галерее | горизонтальная |
| `cabinet.*` | кабинет врача, страницы услуг | **вертикальная** |
| `equipment.*` | секция «Технологии», карточка услуги | горизонтальная |
| `sterilization.*` | стерилизационная | горизонтальная |
| `team.*` | команда, профиль врача | горизонтальная |
| `hero.*` | кадр на первом экране главной, если видео ещё нет | **вертикальная** |
| `entrance.*` | слот зарезервирован, в вёрстке пока не используется | горизонтальная |
| `doctor-1.*` … `doctor-4.*` | карточки врачей (имя файла = `slug` из `DOCTORS`) | вертикальная |

Не кладите один и тот же снимок в несколько слотов: посетитель увидит
одну картинку в разных местах под разными подписями. Лучше оставить честную
заглушку до реальной съёмки — она выглядит как часть дизайна, а не как дыра.

Один и тот же снимок можно положить под двумя именами — например скопировать
`facade.png` в `hero.png`, чтобы фасад появился и на первом экране. Учтите, что
кадр на главной вертикальный: широкий снимок обрежется по бокам.

Фото кадрируется по центру (`object-fit: cover`). Если кадр обрезается неудачно,
поправьте `ratio` у нужного слота в `src/data/clinic.js`.

Фотография с внешнего адреса подключается через `src` в `PHOTOS`:
`{ src: 'https://cdn.example.com/facade.jpg', ratio: '4/3' }` — такое значение
имеет приоритет над файлом из папки.

## 3.1. Видео на первом экране

Первый экран главной — это видеоплеер: один большой ролик и три миниатюры под
ним. Клик по миниатюре меняет её местами с главным роликом (не просто подменяет
источник — активное видео уезжает ровно на место выбранной миниатюры).

Положите ролики в `src/assets/videos/`:

```
video-1.mp4   ← стартовый главный ролик
video-2.mp4   ← миниатюра 1
video-3.mp4   ← миниатюра 2
video-4.mp4   ← миниатюра 3
```

Порядок — по имени файла: первый по алфавиту становится главным. Форматы
`.mp4`, `.webm`, `.m4v`. Рядом можно положить кадр-постер с тем же именем
(`video-1.jpg`) — он сожмётся в WebP и покажется до старта.

В отличие от фотографий, ролики **не** встраиваются в HTML как base64: сборка
копирует их в `assets/videos/` рядом с каждой копией сайта, добавляя к имени хеш
содержимого (`video-1.a39de05e.mp4`). Ролики кешируются браузером на год, и хеш
гарантирует, что заменённый файл посетители увидят сразу. На сайте путь к ролику
идёт от корня (`/assets/videos/…`), поэтому работает на любой странице, в том числе
`/ru/services/therapy`; при открытии файла с диска путь остаётся относительным.
Выкладывать на хостинг нужно и HTML, и папку `assets/`.

Рядом с роликом можно положить облегчённую версию для телефонов —
`video-1.mobile.mp4`: на экранах до 767 px и в миниатюрах грузится она.

**Загрузка.** Сначала показывается постер, а сам ролик подключается, когда первый
экран попал в кадр и страница уже загрузилась (на телефоне плеер ниже первого
экрана — ролик начнёт грузиться при прокрутке к нему). Если в браузере включена
экономия трафика (Save-Data, медленная сеть 2G) или «уменьшение движения»
(`prefers-reduced-motion`), остаётся постер; ролик загрузится, только если
посетитель сам нажмёт Play.

Рекомендации по файлам: H.264, ширина около 1280 px, без звука,
`-movflags +faststart`, до ~8 МБ — сборка предупредит, если файл тяжелее.
Готовые команды ffmpeg — в `src/assets/videos/README.md`.

Пока папка пуста, на месте плеера показывается фотография `hero.*` — вёрстка,
плавающие карточки и параллакс работают как обычно. Подробности и тестовые
клипы для предпросмотра — в `src/assets/videos/README.md`.

## 4. Как пересобрать

```bash
npm install       # один раз: jsdom для QA, sharp для сжатия фотографий
npm run build     # src/ → готовый сайт в dist/
npm run qa        # проверка всех страниц на 6 языках, роутинга, формы и api/booking.js
npm run all       # сборка + проверка
npm run dev       # dist/ на http://localhost:3000 с правилами vercel.json и /api/booking
```

Сборка пишет только внутри репозитория:

```
dist/index.html              сайт — его раздаёт Vercel
dist/assets/videos/          ролики первого экрана
dist/robots.txt              для поисковиков, ссылается на sitemap
dist/sitemap.xml             все страницы × 6 языков с hreflang
index.html, assets/videos/   копия рядом с исходниками для открытия двойным кликом (в .gitignore)
```

Vercel сам ничего не собирает (`buildCommand` в `vercel.json` — заглушка) и раздаёт
закоммиченную папку `dist/`. Поэтому после правок в `src/` выполните `npm run all`
и закоммитьте `dist/` вместе с исходниками. Если изменения не видны — проверьте,
что `npm run build` отработал без ошибок: в конце он печатает список обновлённых файлов.

## 4.1. Адреса страниц и роутинг

У каждой страницы — настоящий адрес без слеша на конце:

```
/ru                       главная
/ru/services              услуги
/ru/services/therapy      страница услуги
/de/contacts              контакты на немецком
```

- **На хостинге** (http/https) переходы идут через History API, без перезагрузки.
  Сервер на любой адрес вида `/ru…`, `/uz…`, `/en…`, `/es…`, `/fr…`, `/de…` отдаёт
  `index.html` — это правила `rewrites` в `vercel.json`, а скрипт уже показывает
  нужную страницу. `/assets/…`, `/api/…`, `robots.txt` и `sitemap.xml` правила не трогают.
- **Слеш на конце.** `trailingSlash: false`: `/ru/` отвечает 308 на `/ru`.
  canonical, hreflang, `og:url`, хлебные крошки и `sitemap.xml` используют адрес
  без слеша — тот, что сервер отдаёт с кодом 200.
- **Корень** `/` открывает сайт и сам переводит на язык посетителя (`/ru`, `/en`…).
- **Старые ссылки** вида `/#/ru/services` (сайт раньше работал на хешах) открываются
  и сразу заменяются на `/ru/services`.
- **Запасной хеш-режим.** Если открыть `index.html` двойным кликом (file://) или
  положить сайт не в корень домена, адреса будут вида `index.html#/ru/services` —
  так сайт работает без настроек сервера.
- **Другой хостинг.** Нужно такое же правило: адреса `/ru…`, `/uz…` и т. д. → `index.html`.
  Без него главная откроется, но прямые ссылки на внутренние страницы дадут 404.

Все адреса строит одна функция — `routePath()` в `src/lib/core.js`; ею же пользуется
сборка для `sitemap.xml`, поэтому sitemap и canonical не расходятся.

## 4.2. Заявки с формы → Telegram

Форма отправляет заявку на `/api/booking` — это функция Vercel `api/booking.js`
(Node.js, без зависимостей). Она проверяет поля на сервере, отсекает ботов
(скрытое поле-ловушка) и пересылает заявку в Telegram клиники. В браузере
персональные данные не сохраняются.

Чтобы заявки приходили, один раз:

1. В Telegram откройте @BotFather → `/newbot`, получите **токен** бота.
2. Создайте группу для администраторов (или используйте личный чат), добавьте туда
   бота и напишите в группу любое сообщение.
3. Узнайте **id чата**: откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` —
   нужное число в `"chat":{"id":…}` (у групп оно отрицательное, например `-1001234567890`).
4. Vercel → проект → Settings → Environment Variables: добавьте `TELEGRAM_BOT_TOKEN`
   и `TELEGRAM_CHAT_ID` (для Production и Preview) и сделайте Redeploy.

Пока переменные не заданы, функция отвечает 503, и сайт показывает демо-сценарий:
экран успеха с просьбой продублировать заявку в Telegram или WhatsApp. Так же форма
ведёт себя, если сайт открыт с диска или функция недоступна. Токен нигде в коде
не хранится — только в настройках Vercel.

Проверить локально с настоящим ботом:
`TELEGRAM_BOT_TOKEN=… TELEGRAM_CHAT_ID=… npm run dev`.

```
src/

  i18n/{ru,uz,en,es,fr,de}.js   словари, структура одинаковая во всех языках
  lib/core.js           i18n, роутер, SEO, деньги
  lib/motion.js         движок анимаций: reveal-сценарии, каскад, параллакс, лоадер
  lib/icons.js          ~53 иконки
  assets/photos/        фотографии клиники — см. раздел 3
  components/           ui.js (кнопки, карточки, маски заголовков, орбита),
                        layout.js (шапка, меню, футер, панели), booking.js (форма записи)
  sections/             независимые блоки главной: hero, trust, about-band,
                        services-grid, technology, why, process, prices-teaser,
                        doctors-stage, reviews-strip, booking-panel, contacts-panel
  pages/                по файлу на раздел; главная — только композиция секций
  styles/               01-tokens, 02-motion, 03-shell, 04-sections, 05-forms

build.mjs               сборка dist/ (HTML, ролики, robots.txt, sitemap.xml)
qa.mjs                  проверка собранного сайта и функции
dev-server.mjs          локальный сервер с правилами vercel.json (npm run dev)
```

Тексты нигде не зашиты в вёрстку — только ключи. Чтобы поправить формулировку,
достаточно найти её в файле нужного языка.

Порядок блоков главной задаётся одним массивом в `src/pages/home.js` — секции можно
менять местами, убирать и добавлять, не трогая их внутренности.

## 6. Дизайн-система

- **Цвет**: белый и off-white, глубокий фирменный синий (`--navy: #003882` из логотипа),
  мягкий голубой и холодный серый. Никаких посторонних акцентных цветов.
- **Типографика**: Manrope для крупных заголовков, Inter для текста,
  Playfair Display italic — акцентное слово в заголовке (поддерживает кириллицу и латиницу).
- **Ритм фона**: белый → светло-голубой → тёмно-синяя секция → белый → нейтральный камень.
- **Тени** мягкие, с синим подтоном; границы тонкие. Интерфейс должен ощущаться лёгким.
- **Раскладка услуг** — editorial-сетка на 12 колонок: ширина и тон каждой карточки
  берутся из массива `SERVICE_LAYOUT` в `components/ui.js`, а не из вёрстки.

## 7. Анимация

Движок — `src/lib/motion.js`. Разметка объявляет сценарий, скрипт решает когда его запустить.

| Атрибут | Что делает |
|---|---|
| `data-reveal="up \| up-sm \| fade \| left \| right \| scale \| rise \| blur \| clip"` | сценарий появления блока |
| `data-stagger="90"` на контейнере | каскад: детям раздаются задержки по 90 мс |
| `data-stagger-from="140"` | сдвиг начала каскада |
| `<span class="mask"><span class="mask__i">…` | строка заголовка выезжает из-под маски |
| `class="reveal-img"` | изображение проявляется с clip + плавным зумом |
| `class="parallax" style="--depth:1.2"` | очень лёгкий параллакс от курсора |
| `data-rail` | линия таймлайна «чертится», когда секция попадает в кадр |

Переход между страницами использует View Transitions там, где браузер их поддерживает,
и обычную отрисовку везде остальном.

**Производительность.** Крупные размытые пятна статичны — анимировать `transform` на
элементе с `filter: blur(70px)` слишком дорого. `backdrop-filter` используется точечно.
`will-change` не висит на сотне элементов. Замер на собранном файле: FCP ≈ 60 мс,
DOMContentLoaded ≈ 45 мс, 718 узлов DOM на главной.

**prefers-reduced-motion.** Если пользователь отключил анимацию, все блоки видны сразу,
параллакс и переходы выключены, сайт полностью рабочий.

## 8. Тон текстов

Формулировки намеренно осторожные: нет «без боли», «гарантированного результата»,
«лучшей клиники». Вместо этого — «зависит от клинической ситуации», «врач объяснит»,
«решение принимает пациент». Если будете дописывать тексты, стоит держать ту же интонацию:
в правовом блоке прямо сказано, что клиника не гарантирует конкретный медицинский результат.

## 9. Переход на Next.js

Архитектура к этому готова: `data/`, `i18n/` и `sections/` переносятся без изменений,
`pages/` становятся серверными компонентами, а адреса `/ru/services/...` уже совпадают
со схемой `app/[lang]/...` — ссылки менять не придётся.
Смысл переезда — статическая генерация HTML для каждой страницы и языка: сейчас
поисковики видят корректные мета-теги и микроразметку, но контент подставляется скриптом.

## 10. Что проверено

`npm run qa` обходит все 132 адреса из `sitemap.xml` (22 страницы × 6 языков) и страницы 404:
нет пустых страниц, битых ссылок, картинок без alt, кнопок без подписи, смешения языков,
